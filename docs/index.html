Ekranlar

Aşağıdaki görüntüler uygulamanın web sürümünden otomatik olarak üretildi: node docs/demo/capture.mjs web paketini derler, yerel bir sunucuda yayınlar ve Chrome'u DevTools protokolü üzerinden sürerek her ekranı iki temada da yakalar. Görsele tıklayarak büyütebilirsiniz.

02

Mimari

Sunucu kodu yok; uygulama doğrudan Firestore ile konuşur ve yetkilendirme tamamen güvenlik kurallarındadır. Katmanlar arasındaki ayrım nettir: lib/ Firebase'i tanımayan saf iş mantığıdır, services/ ağ katmanıdır, app/ yalnızca bu ikisini birleştirir.

Dosya yapısı

app/ — rotalar (dosya = ekran)
├── _layout.tsx — göç, oturum, tema sağlayıcı
├── (tabs)/ — index · expenses · explore · history
└── kayit · profil · feedback
components/ui/ — tasarım sistemi (20 bileşen)
theme/ — jetonlar + ThemeProvider
lib/ — prim · storage · format · ids
services/ — firebase · auth · backup · users · feedback
admin-panel/ — tek dosya web paneli
docs/ — bu doküman + ekran görüntüsü üretici
firestore.rules — tek yetkilendirme noktası

Durum ve veri akışı

Global durum kütüphanesi yok. Paylaşılan tek durum tema (ThemeProvider) ve oturum (useOturum) — ikisi de abonelik tabanlı, dolayısıyla bir ekranda değişince diğerleri anında güncellenir.

Kayıt verisi ekranlar arasında AsyncStorage üzerinden paylaşılır: her ekran odağa geldiğinde diskten yeniden okur ve normalleştirir. 

// her sekmede tekrarlanan desen
useFocusEffect(useCallback(() => {
  let iptal = false;
  maasKayitlariniOku().then((liste) => {
    if (!iptal) setKayitlar(liste);
  });
  return () => { iptal = true; };
}, []));
Yazma yolu: önce AsyncStorage (beklenir), sonra yedegeYaz() (beklenmez). Bulut yazması başarısız olsa bile kullanıcının işlemi tamamlanmış sayılır.

04

Prim hesaplama motoru

İş kuralı iki orandan ibaret. Önceki sürümde bu formül "Maaş" ve "Hızlı" ekranlarında ayrı ayrı yazılıydı; artık tek kaynak lib/prim.js.

Tek kaynak

// lib/prim.js
export const PRIM_ORANLARI = {
  kurulum:   0.025,
  haftaIci:  0.025,
  haftaSonu: 0.035,
  arac:      0.035,
};

export function primHesapla(maas, adetler) {
  const anaMaas = sayiyaCevir(maas);
  const kalemler = PRIM_KALEMLERI.map((k) => {
    const birim = anaMaas * PRIM_ORANLARI[k.key];
    const adet  = sayiyaCevir(adetler[k.key]);
    return { ...k, birim, adet, tutar: birim * adet };
  });
  const primToplam = kalemler.reduce((t, k) => t + k.tutar, 0);
  return { anaMaas, kalemler, primToplam,
           toplam: anaMaas + primToplam };
}
Bu fonksiyondan besleniyor: Maaş ekranı, Hızlı hesap ekranı, Geçmiş kırılımı ve kayıt şeması üreten kayitOlustur(). Oranı değiştirmek tek satırlık bir işlem.
05

Kimlik ve yedekleme

Cihaz değiştirmede veriyi geri getirmek, o verinin sahibi olduğunuzu kanıtlamayı gerektirir. Önceki sürümde "kanıt" yalnızca e-posta adresini yazmaktı — bu, adresi bilen herkesin veriye erişmesi demekti. Yeni model iki katmanlı.

06

Güvenlik kuralları

Sunucu kodu olmadığı için firestore.rules tek savunma hattı. Kural dosyası 18 satırdan 129 satıra çıktı: her koleksiyon için sahiplik, alan doğrulaması ve boyut sınırı eklendi; tanımsız her yol kapatıldı.

Yedek kuralı — önce ve sonra

Önce — herkes okuyabiliyordu
match /yedekler/{docId} {
  allow read, write: if request.auth != null;
}
// docId = kullanıcının e-postası
Sonra — yalnızca sahibi
match /yedekler/{uid} {
  allow get: if sahibi(uid);
  allow create, update: if sahibi(uid)
                        && gecerliYedek();
  allow list: if false;
}
// uid = tahmin edilemez oturum kimliği

Yardımcılar

// Anonim oturumlar veri sahibi olamaz
function kaliciHesap() {
  return girisYapti()
    && request.auth.token.firebase
         .sign_in_provider != 'anonymous';
}

function sahibi(uid) {
  return kaliciHesap() && request.auth.uid == uid;
}

// Tanımsız her yol kapalı
match /{document=**} {
  allow read, write: if false;
}
Dağıtmayı unutmayın: Kurallar depoda güncel olsa da npm run deploy:rules çalıştırılana kadar üretimde eski kurallar geçerlidir.
07

Kapatılan açıklar ve düzeltilen hatalar

Her madde, düzeltmeden önce gerçekten oluşabilecek bir senaryoyu tarif ediyor.

!

Bulut yedeği herkese açıktıKritik

yedekler/{eposta} kuralı yalnızca oturum açmış olmayı arıyordu ve belge kimliği tahmin edilebilir bir e-postaydı. Anonim oturum açan herhangi biri, e-postasını bildiği bir kullanıcının tüm maaş ve harcama geçmişini okuyabilir ve üzerine yazabilirdi. Düzeltme: belge kimliği oturum UID'si oldu, kural sahipliği doğruluyor.

!

Yönetim panelinde depolanmış XSSKritik

Kartlar innerHTML ile kuruluyor ve kullanıcıdan gelen mesaj, isim, eposta alanları kaçışlanmadan gömülüyordu. Uygulamadan gönderilen bir geri bildirim, yöneticinin tarayıcısında betik çalıştırabilirdi — panel oturumu açıkken bu, tüm kullanıcı verisine erişim demekti. Düzeltme: tüm kullanıcı verisi textContent ile yazılıyor.

!

Kullanıcı belgelerinde sahiplik denetimi yoktuYüksek

kullanicilar üzerinde update, belge kimliğini bilen her oturuma açıktı. Düzeltme: belge kimliği UID oldu; sahip kendi profilini yazabiliyor, yönetici yalnızca silme bayrağını değiştirebiliyor. Alan adları ve uzunlukları da kuralda doğrulanıyor.

!

Ağ yanıt vermezse uygulama açılmıyorduYüksek

Açılış signInAnonymously çağrısını bekliyordu; bağlantı kurulamadığında uygulama yükleme göstergesinde kilitli kalıyordu. Bu, tarayıcı testinde doğrudan gözlemlendi. Düzeltme: kimlik doğrulama arka planda yürüyor, arayüz yerel veri hazır olur olmaz açılıyor.

!

Oturum her açılışta sıfırlanıyorduYüksek

Firebase JS SDK'sı React Native'de varsayılan olarak belleği kullanır; getAuth() ile açılan oturum uygulama kapanınca kayboluyordu. UID ile anahtarlanan yedek bu hâlde çalışamazdı. Düzeltme: initializeAuth + AsyncStorage kalıcılığı.

!

Yanıtlanmayan geri bildirim "yanıtlandı" görünüyorduOrta

Panel, Firestore durumunu e-posta gönderiminden önce güncelliyordu; EmailJS çağrısı başarısız olsa bile kayıt "Yanıtlandı" oluyor ve kullanıcı hiçbir zaman yanıt almıyordu. Düzeltme: sıra tersine çevrildi ve HTTP durumu kontrol ediliyor.

!

Çakışmaya açık kayıt kimlikleriOrta

Math.random().toString() ile üretilen kimlikler çakışabiliyordu; çakışma hâlinde silme işlemi yanlış kaydı siler, birleştirme veri kaybettirirdi. Düzeltme: crypto.randomUUID(), ayrıca göç sırasında mevcut çakışmalar tespit edilip yeniden kimliklendiriliyor.

Arayüz ve doğruluk düzeltmeleri

  • React Compiler çökmesi: koşullu render edilen JSX içinde secilenKayit.id erişimi memo bağımlılığına çıkarılıp koşuldan bağımsız çözümleniyor ve altı ekran beyaz açılıyordu. Tarayıcıda yakalandı, güvenli erişimle düzeltildi.
  • Aylar takvim sırasına göre sıralanıyor — eskiden ekleme sırası belirleyiciydi.
  • Sekme etiketleri kırpılmıyor — "Maaş" ve "Geçmiş" varsayılan etiket kutusunda "Maas"/"Gecmis" olarak görünüyordu.
  • Geri bildirim ekranı temaya bağlandı — koyu temada beyaz kalıyordu.
  • expo-navigation-bar SDK 57'de kaldırılan setBehaviorAsync çağrısı temizlendi.
  • Eski kayıt biçimi için sürümlü göç eklendi — mevcut kullanıcılar veri kaybetmiyor.

Kalan işler

  • Kuralları dağıtın: npm run deploy:rules — bu yapılana kadar üretimde eski kurallar geçerli.
  • EmailJS alan adı kısıtlaması: panelden Account → Security → Allowed origins altına yayın alan adını ekleyin; anahtarlar istemcide olduğu için tek koruma bu.
  • Firebase Authentication ekranından Email/Password sağlayıcısının açık olduğunu doğrulayın.
  • Yönetici e-postası doğrulandıktan sonra kural dosyasındaki email_verified satırının yorumunu kaldırın.
  • Prim oranlarını uzaktan yapılandırılabilir hâle getirmek (şu an kodda sabit).
